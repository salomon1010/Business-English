# BE Mastery Welding — Play store assets

Pasted into Play Console by hand; nothing in the repo uploads them.
See `docs/APP_SPLIT.md` § Store actions for the full owner checklist.

| file | where it goes | limit |
|---|---|---|
| `listing-title.txt` | App name | 30 characters |
| `listing-short-description.txt` | Short description | 80 characters |
| `listing-full-description.txt` | Full description | 4,000 characters |
| `play-icon-512.png` | App icon | 512×512 PNG |

The icon is generated from the app's own `welding-mastery-logo.svg`, the same
mark the Welding Mastery hub uses, so the listing, the launcher icon and the
app agree. The Android launcher icons live in
`mobile/android/android/app/src/welding/res/mipmap-*`.

## Screenshots — `phone/`, done

Six 1080×2400 shots of the Welding app itself, taken 12 Oct 2026:

| file | screen |
|---|---|
| `01-journey` | the Welding road map — 12 stages, Pipefitter, two stages done |
| `02-practice` | the five Welding practice tools |
| `03-simulation` | the workshop conversation with the crew |
| `04-lines` | workplace lines to shadow, in the learner's own trade |
| `05-progress` | the Welding programme's progress page |
| `06-phrasebank` | the Welding phrase bank |

Regenerate with:

```
python3 -m http.server 8766 --bind 127.0.0.1
BASE=http://127.0.0.1:8766 OUT_ROOT=welding PROGRAMME=welding \
  node scripts/store-art/shoot.js phone
```

`PROGRAMME=welding` hands the iframe `window.BE_BUILD={track:"welding"}` — the
same marker the store bundle carries — so the app under the camera IS the
Welding app: the router refuses the General English pages and Home draws no
programme card. The seed gives the Welding programme its own history, because
session progress is keyed `welding:w<N><Day>` and the General English keys would
leave the road map reading 0%.

Two screens are deliberately absent. **Shadow**, because every dense screen in
the studio renders third-party YouTube artwork — the same rule the General
English set follows. **Welding Mastery**, because its headline numbers are
account-bound, so without a signed-in account the hub draws "Sign in to play"
over 0 XP; honest, but a poor first impression in a listing.

Tablet shots (1440×2560) are in `tablet/`, the same six screens:

```
BASE=http://127.0.0.1:8766 OUT_ROOT=welding PROGRAMME=welding \
  node scripts/store-art/shoot.js tablet
```

## Feature graphic — `feature-graphic.png`, done

1024×500, generated by `scripts/store-art/feature-graphic.mjs` from the app's
own assets: the Welding Mastery mark, the Welding gold accent on the Welding
navy, and one of the programme's own photographs. No third-party artwork — the
same rule the screenshot sets follow.

```
python3 -m http.server 8767 --bind 127.0.0.1
node scripts/store-art/feature-graphic.mjs welding
```

The General English variant (`general`) writes to
`playstore/feature-graphic-general.png` and deliberately does **not** overwrite
`playstore/feature-graphic.png`, which is what the live listing uses.

**Nothing further is needed from the owner for artwork.** The General English
sets must not be reused for this listing: they show General English screens.

Count the full description before editing: Play rejects anything over 4,000.
